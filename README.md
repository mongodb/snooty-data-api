# snooty-data-api

Snooty Data API is a REST API that returns build artifacts for docs builds.

## Setup

### Node

Node 18 was used to start this project. Please make sure you have Node 18 installed locally. If you have [nvm](https://github.com/nvm-sh/nvm), you can run `nvm use` to switch to the expected version of Node.

### Install

Use `npm` v8 to install dependencies:

```
npm ci
```

### .env

Use the `sample.env` file to help configure a local `.env` file.

| Variable                   | Required | Description                                                                                                            |
| -------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------- |
| `ATLAS_URI`                | yes      | Connection string for the database holding build artifacts.                                                            |
| `DOCSETS_API_URL`          | yes      | Docsets API that `/projects` reads versioning data from. See [Versioning data](#versioning-data).                      |
| `SNOOTY_ENV`               | yes      | Selects which host and prefix are used to build `fullUrl`. Must be `dotcomprd` or `dotcomstg`; any other value throws. |
| `SNOOTY_DB_NAME`           | no       | Database for build artifacts. Defaults to `snooty_dev`.                                                                |
| `SNOOTY_PROD_DB_NAME`      | no       | Database for production deployments, as opposed to staging. Defaults to `snooty_dev`.                                  |
| `BUILDER_USER`             | no       | User who performed the build. Defaults to `docsworker-xlarge`.                                                         |
| `PORT`                     | no       | Port for the app server. Defaults to `3000`.                                                                           |
| `DOCSETS_CACHE_TTL_MS`     | no       | How long a fetched docsets response is cached. Defaults to `600000` (10 minutes).                                      |
| `DOCSETS_FETCH_TIMEOUT_MS` | no       | Timeout for the docsets API request. Defaults to `10000`.                                                              |

`SNOOTY_ENV` is a common source of confusion: the values are `dotcomprd` and `dotcomstg`, not `prod`/`prd`/`dev`. An unrecognized value used to resolve to an empty host and silently produce `fullUrl` values like `//upcoming`, so it is now rejected outright.

### Database

If a local database is desired for development, make sure to install [MongoDB Community Edition](https://www.mongodb.com/docs/manual/tutorial/install-mongodb-on-os-x/) via Homebrew. Otherwise, an Atlas connection string should be used in your `.env` file with `snooty_dev` as the database.

The build data to be used by this API server is saved by the Autobuilder's [Persistence Module](https://github.com/mongodb/docs-worker-pool/tree/master/modules/persistence). If using a local database, feel free to use the Persistence Module to help save bundled artifacts generated by the [Snooty Parser](https://github.com/mongodb/snooty-parser).

### Versioning data

The `/projects` listing route does not read from a database. It fetches project and version data over HTTP from the docsets API, configured by `DOCSETS_API_URL`:

- Production: `https://docs-on-nextjs.netlify.app/api/docsets/`
- Staging: `https://preprd--docs-on-nextjs.netlify.app/api/docsets/`

This replaced a direct connection to the Atlas `pool` database (`repos_branches` and `docsets`), so `POOL_ATLAS_URI` and `POOL_DB_NAME` are no longer used. Both routes are currently public; no credentials are required.

The response is cached in memory. Behavior on refresh:

- The cache is warmed at startup, without blocking the server from starting.
- A refresh failure with a cache present logs a warning and serves the stale copy.
- A refresh failure with no cache returns a 500. An empty, non-array, or non-2xx response is treated as a failure and is never cached, since silently serving zero projects would look like success to consumers.

Versioning is migrating out of the `pool` database and into TypeScript files in `docs-mongodb-internal`. The docsets API currently serves the legacy shape, where each entry has a `branches` array and env-keyed `url`/`prefix` maps. It will later serve a new shape, where each entry has a `versions` array and a single `prefix` string. This service detects the shape per entry and maps both onto the same response, so consumers see no change. Two differences are unavoidable once the new shape lands:

- `gitBranchName` becomes the version's `versionName`. For projects whose git branch differed from their published URL slug, the value changes, for example the manual's `master` becomes `v7.0`. The `fullUrl` is unaffected.
- `repoName` no longer exists upstream and mirrors `project`, so it changes for most projects, for example `docs-node` becomes `node`.

## Running

To start the server, run:

```
npm run dev
```

By default, the server should be accessible through http://localhost:3000/.

## Testing

Tests are ran by [Jest](https://jestjs.io/) and rely on [Supertest](https://github.com/ladjs/supertest) for testing Express route logic. [MongoDB Memory Server](https://github.com/nodkz/mongodb-memory-server) is used to help perform MongoDB queries in tests without having to worry about running a local MongoDB instance.

To run tests, use:

```
npm run test
```

## Linting

We use `eslint` for linting and `prettier` for formatting. `prettier` is configured to run on lint, so feel free to just use:

```
npm run lint
```

If there are errors flagged through `prettier`, use:

```
npm run format:fix
```

## Releasing

To release a new version of the data API to production, tag a new version from the [Releases page](https://github.com/mongodb/snooty-data-api/releases). That tag will then be promoted to prod.

## Endpoints

The following are the base URLs for the Snooty Data API:

- `https://snooty-data-api.docs.staging.corp.mongodb.com/`
